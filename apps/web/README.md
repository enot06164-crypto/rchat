# Веб-клиент rchat (этап H-Final)

Официальный веб-интерфейс — **реплика Telegram WebK** (тема Amethyst Dark).
Геометрия, расположение кнопок и кривые анимаций сверены с исходниками
`TelegramOrg/Telegram-web-k` (`src/scss/base.scss`, `src/scss/partials/
_chat.scss`, `_chatBubble.scss`, `_chatVariables.scss`,
`src/components/chat/input.ts`): взяты **числовые параметры** (радиусы,
сдвиги, тайминги, easing-кривые) и правила раскладки. Код клиента, SVG-пути
и обои написаны с нуля — ничего не скопировано дословно.

- **SolidJS 1.9 + TypeScript (strict)** — точечная реактивность, без Virtual DOM.
- **Vite 5** — dev-сервер и сборка; **SCSS** — палитра и стили.
- **lucide-solid** — иконки (карандаш, самолётик, галочки, контекстное меню).
- Протокол — **JSON FFI без изменений** (`docs/ffi.md`): WebSocket-шлюз
  (`bindings/python/rchat/gateway.py`) проксирует `rchat_send_json` и
  ретранслирует события ядра в браузер.

## Запуск с нуля (три терминала)

```bash
# 0) один раз: собрать ядро и установить зависимости
cargo build -p rchat-ffi --bin rchat-server
cargo build --bin rchat-server
(cd apps/web && npm install)

# шлюзу нужен внешний пакет websockets (не входит в SDK):
python3 -m venv .venv-gateway
uv pip install --python .venv-gateway/bin/python websockets   # или pip install websockets в venv

# 1) сервер разработки (plaintext только для localhost)
cargo run --bin rchat-server -- \
    --db /tmp/rchat-web/server.sqlite3 \
    --listen 127.0.0.1:9000 \
    --plaintext-insecure --allow-dev-plaintext-chats

# 2) шлюз: один процесс обслуживает несколько профилей (аккаунтов).
#    --data-dir — корень профилей: «default» — сам корень, остальные —
#    в <корень>/accounts/<имя> (та же раскладка, что у CLI --account).
PYTHONPATH=bindings/python .venv-gateway/bin/python -m rchat.gateway \
    --data-dir /tmp/rchat-web \
    --server ws://127.0.0.1:9000 \
    --port 8080

# 3) веб-клиент (Vite проксирует /ws на шлюз)
cd apps/web && npm run dev          # http://localhost:5173
```

Для сервера с TLS (`wss://`, самоподписанный сертификат) шлюз принимает
`--tls-fingerprint` или `--tls-insecure` (Как в CLI; вне dev TLS обязателен).

## Что уже работает

**Каркас (как в WebK):** страница с колонками-карточками (отступы 16px,
радиус 15px, мягкая тень): левая колонка 360px, центральная область чата и
правая колонка «Информация» 360px, которая **вытесняет** чат, а не
перекрывает пузыри.

**Приватный режим по запросу:** в меню чата (кнопка «⋮» в шапке) есть пункт
«Запросить приватный режим» — только для личного чата, который ещё не в E2E.
Запрос приходит **сообщением в чат** (служебное сообщение-карточка, а не
модальным окном), карточка стоит **по центру ленты**: светящийся замок,
заголовок «Запрос на приватный режим», пояснение про защиту от копирования и
скриншотов и статус «Ожидание подтверждения от пользователя…».  У отправителя
в карточке — кнопка «Отменить запрос», у собеседника — «Принять» и
«Отклонить».  После ответа карточка меняется на итог («Чат переведён в
приватный режим» / «Запрос отклонён»).  При принятии чат переводится в
сквозное шифрование; старые сообщения остаются как есть.

**Обратное предложение:** в том же меню, когда чат уже в приватном режиме,
есть пункт «Предложить отключить приватный режим» — та же карточка в чате, но
с другим текстом (чат вернётся в обычный режим: новые сообщения сможет
прочитать сервер, старая переписка останется зашифрованной).  Переключение
делает сервер по согласию собеседника, а не сразу.

Служебная карточка не остаётся пустой: у неё есть короткий текст
(«Запрос на приватный режим» / «Предложение отключить приватный режим») —
он виден в превью последнего сообщения в списке чатов и в ответе на карточку
(и в поле ввода, и в цитате отправленного сообщения).

**Новый чат:** при вводе username идёт поиск по пользователям (сервер знает
список аккаунтов) и показывается выдача — можно выбрать собеседника в один
клик; переключатель «Приватный чат» по умолчанию соответствует режиму чатов
из настроек.

**Левая колонка:**
- левая колонка — плоская серая карточка (обои только в области чата);
- Шапка 56px: кнопка-гамбургер (40×40px) открывает фирменное меню аккаунта
  (полупрозрачное, `backdrop-filter: blur(25px)`, раскрытие `scale(0.85) →
  1`): аватар с кольцом онлайна, имя, `@username`, статус соединения; ниже —
  список аккаунтов этого браузера (аватар и имя, активный подсвечен) и
  «Добавить аккаунт»; затем «Новый личный чат», «Настройки», «Выйти из
  аккаунта». Если в поиске есть текст — гамбургер превращается в стрелку
  «Назад» и очищает поиск;
- овальное поле поиска (42px, радиус 21px): фиолетовая обводка и иконка лупы
  при фокусе, кнопка очистки `×` справа;
- поиск по сообщениям: ниже списка чатов — раздел «Сообщения» с найденными
  фрагментами (облачный режим: сервер расшифровывает содержимое ключом чата
  и ищет по нему; в приватных чатах содержимое серверу недоступно);
- превью последнего сообщения в списке чатов берётся из ответа ядра
  (`last_message`), поэтому после перезагрузки страницы чаты не показывают
  «Нет сообщений» — открывать чат не нужно;
- элемент чата (аватар 54px, имя, время, превью со статус-иконками
  и именем отправителя в цвете палитры ядра, круглый бейдж непрочитанных,
  замок у приватных чатов);
  активный чат — насыщенно-фиолетовая плашка `#8774e1` с белым текстом;
- плавающая круглая кнопка нового чата 54px в акценте с
  пружинящей анимацией `cubic-bezier(.34, 1.56, .64, 1)`.

**Шапка чата (56px):** аватар 42px, имя, статус («в сети» / «был(а) недавно»
при `presence_changed`, иначе честное «E2E защита»); справа кнопки WebK:
поиск, звонок, **переключатель боковой панели информации** (`PanelRight`,
горит фиолетовым при открытой колонке) и меню.

**Правая колонка «Информация» (360px)** — по типу чата:
- **личный чат** — карточка профиля: аватар 100px, имя, `@username`,
  статус присутствия, строка «Уведомления» (колокольчик + тумблер) и вкладки
  **Медиа | Файлы | Голосовые | Ссылки | Группы**;
- **группа** — те же вкладки, но первой идёт **Участники** (состав берётся
  из `get_chat_members`), а вкладка «Группы» заменена на «Участники»;
- вкладка «Группы» (общие группы с собеседником) считается **по данным
  ядра**: `get_chats` + `get_chat_members` по каждой группе (отдельной
  команды «общие чаты» в FFI нет);
- Медиа / Файлы / Голосовые / Ссылки — **честные пустые состояния**: ядро
  пока хранит только текстовые сообщения (`content_kind: "text"`), команд
  загрузки вложений и фильтрации по медиа в FFI нет.

**Лента сообщений:**
- фоновый дудл-паттерн Telegram (opacity 0.05) поверх `#0e0e0e`;
- **группировка пузырей как в WebK**: сообщения одного автора идут плотной
  группой (2px), между группами — 6px; внешние углы 15px, смежные 5px;
- **хвостик — только у последнего пузыря серии** (как в Telegram): у первых
  пузырей серии хвостика нет, у последнего — маленький скруглённый выступ
  снизу-сбоку (для исходящих зеркально).  Серия — это сообщения одного
  автора, отправленные подряд: пауза больше пяти минут (или другой день)
  разрывает её, и тогда у каждого пузыря свой хвостик;
- аватар участника — только в групповых чатах и только у последнего
  сообщения группы (в личных чатах колонка под аватар не резервируется);
- время и галочки обтекают текст (`float: right`), как `.time` в WebK;
- капсула-разделитель дат («Сегодня» / «Вчера» / «16 сентября») с
  полупрозрачным фоном и blur;
- кнопка «вниз» с бейджем пропущенных сообщений; новые сообщения не
  автоскроллят ленту, если пользователь читает историю;
- **реплаи**: ПКМ → «Ответить», двойной клик по пузырю или кнопка ответа при
  наведении (с «мостиком» к краю пузыря, чтобы кнопку можно было нажать);
  `send_message` уходит с `reply_to_server_id`, цитата рендерится внутри
  пузыря (полоса `#8774e1`);
- **переход к сообщению по цитате**: клик по полю ответа внутри пузыря
  прокручивает ленту к исходному сообщению и ненадолго подсвечивает его
  (фиолетовая обводка, как в Telegram).  Если сообщения нет в загруженной
  ленте, веб подгружает более старые страницы истории (`fetch_history`) и
  переходит уже к нему; если его нет и там — показывает уведомление
  «Сообщение не найдено»;
- **удаление** собственного сообщения (ПКМ → «Удалить», FFI
  `delete_message`): пузырь исчезает из ленты полностью, без «призрака»;
- копирование текста сообщения (ПКМ → «Копировать текст»).

**Строка ввода (порядок кнопок как в WebK):** скрепка слева, текстовое поле
по центру, смайлик справа от поля, круглая фиолетовая кнопка отправки 40px
последней; иконки микрофона и самолётика живут в DOM одновременно и плавно
сменяют друг друга (`grow-icon` из WebK). Блок ответа — фиолетовая иконка,
автор, цитата и крестик отмены.

**Вложения (поддерживает ядро, этап H-Final):**
- кнопка скрепки открывает выбор файла (можно выбрать **несколько** — соберётся
  альбом-сетка, как в Telegram);
- кнопка микрофона (когда поле пусто) **записывает голосовое** (MediaRecorder);
  повторное нажатие останавливает запись;
- файл едет **отдельным блобом**, как в Telegram: клиент шифрует его
  случайным ключом (XChaCha20-Poly1305) и заливает шифротекст на сервер
  частями, а в сообщение кладёт только ссылку на блоб и ключ — сервер не
  видит ни текст, ни содержимое файла;
- фото сжимается по-телеграммовски: ресайз до 1280px по большей стороне +
  JPEG, кнопка «Без сжатия» отправляет исходный файл;
- у видео генерируется постер-кадр (отдельный блоб, как thumbnail);
- голосовое пишется в Opus, пики звуковой волны считаются в браузере и
  рисуются полоской;
- в пузыре фото/видео показываются превью, файл — карточкой со скачиванием,
  голосовое — волной и плеером; содержимое подтягивается из ядра и кэшируется;
- вкладки шторки «Информация» (Медиа / Файлы / Голосовые / Ссылки) показывают
  **реальные** данные из загруженной истории; «Ссылки» выбирает первую ссылку
  из текста;
- ограничение ядра: вложение до 16 МиБ; содержимое подтягивается из ядра
  отдельной командой `download_attachment` (ядро само скачивает блоб и
  расшифровывает); файлы лежат на диске сервера (каталог `blobs`), в БД —
  только метаданные;
- видео пока не стримится: воспроизведение начинается после полной загрузки
  (Telegram переставляет `moov`-атом в начало файла — это требует
  перепаковки MP4, отдельная задача).

**Прочее:** вход/регистрация (карточка 360px), мгновенная доставка с
оптимистичной вставкой и статусами (часы → галочка → двойная → ошибка),
Enter — отправка, Shift+Enter — перенос строки, тумблер уведомлений в
шторке, выход из аккаунта, deep-link `/?chat=<chat_id>`, dev-хук
`window.__rchat.state`; события ядра применяются реактивно
(connection_state_changed, chat_upserted, message_received/updated,
outbox_changed, receipt_updated, presence_changed), после `event_lagged`
хранилище перечитывается из ядра.

## Ошибки и действия

Ошибки ядра и сервера приходят типизированными кодами (`docs/ffi.md` §6), а
пользователю показываются понятным текстом и подходящим действием
(`apps/web/src/services/errors.ts`):

| Ситуация | Что видит пользователь | Действие |
| --- | --- | --- |
| Нет связи с локальным шлюзом | «Нет связи с шлюзом» | «Подождать» (переподключение идёт само) |
| Шлюз есть, ядро не связано с сервером | «Нет связи с сервером» | «Подождать» |
| Тайм-аут операции | «Не дождались ответа» | «Повторить» |
| Сессия истекла или отозвана | «Сессия закончилась» | «Войти» |
| Неверный логин или пароль | «Неверный логин или пароль» | — |
| Нет прав на действие | «Нет доступа» | — |
| Превышен лимит | «Слишком много запросов» | «Подождать» |
| Файл или сообщение слишком велики | «Слишком большой файл» | «Выбрать файл» |
| Нет ключей расшифровки | «Нет ключей для расшифровки» | «Подождать» |
| Неизвестный код | «Что-то пошло не так» | «Повторить» |

Правила:
- текст составляется по подтверждённому коду; из ошибки WebSocket или
  неизвестного исключения не делается вывод «нет интернета»;
- неизвестная ошибка показывается обезличенно — без технических деталей
  (пароли, токены, ключи и тексты переписки не раскрываются);
- ошибка прикреплена к своему чату и аккаунту: в других чатах она не
  показывается, и одинаковые уведомления не повторяются;
- ошибка отправки **до** постановки в очередь сохраняет введённый текст и
  файлы; после постановки сообщение остаётся в очереди, а кнопка «Повторить»
  возвращает в очередь ту же запись (новой копии не появляется — ключ
  идемпотентности сохраняется).

## Понятные ограничения v1 (что НЕ входит в этап H-Final)

- Счётчик «непрочитанных» — **локальный** и не переживает перезагрузку
  страницы; отметка `mark_read` отправляется при открытом чате, чтобы
  собеседник видел «прочитано».
- `presence_changed` применяется только как подзаголовок «в сети» /
  «был(а) недавно»; пока событие не приходило в этой сессии — показываем
  «E2E защита» (честный статический факт).
- **Реакции и пересылка не реализованы** (в ядре нет соответствующих
  методов): смайлик и пункт меню «Переслать» — визуальные заглушки.
- Отправка вложений ограничена **128 КиБ** на файл: вложение едет внутри
  зашифрованного payload, а тот должен влезть в один кадр сообщения
  (лимит кадра транспорта — 1 МиБ, лимит сообщения сервера настраивается
  `max_message_bytes`).
- Иконки поиска/звонка/меню в шапке чата — заглушки v1 (поиск по чату и
  звонки появятся позже); гамбургер открывает меню аккаунта, а не папки
  чатов.
- Тумблер «Уведомления» в шторке — локальный, не синхронизируется с ядром.
- **Режим чатов** (облачный/приватный) переключается в настройках клиента и
  применяется только к новым чатам; уже созданные чаты сохраняют режим.
  В приватных чатах поиск по сообщениям на сервере не работает — там нужна
  выдача по локальной базе устройства (в планах).
- Зеркальное echo собственного сообщения от ядра (`local_id` вида `s:<id>`,
  body null) дедуплицируется по `server_id` (`message_updated` возвращает
  каноническую запись с `server_id`); история — стартовой страницей
  `get_messages(limit=100)` (пагинация «вверх» — не реализована).
- **Аккаунты в браузере.** Аккаунтов может быть несколько: у каждого своё
  соединение с ядром (свой профиль шлюза, своя БД и ключи) и своё состояние,
  все они подключены одновременно. Список аккаунтов — в **меню профиля
  (бургер)**: аватар и имя каждого, активный подсвечен; в списке только
  аккаунты, в которые действительно вошли (пустые профили не показываются).
  Внизу — «Добавить аккаунт»: открывается **отдельный полноэкранный экран**
  входа (как в Telegram Web) с вкладками «Вход» / «Регистрация»; профиль
  создаётся по логину пользователя, и аккаунт появляется в списке только
  после успешного входа. Переключение аккаунта — мгновенное, без
  перезагрузки. Профиль вкладки хранится в `sessionStorage`, поэтому **две
  вкладки могут держать разные аккаунты** (как Telegram Web A/B).

## Отладка

- `window.__rchat.state` — снимок reactive-хранилища в DevTools (только
  dev-сервер Vite).
- Deep-link `http://localhost:5173/?chat=<chat_id>` сразу открывает чат
  (для смоков и закладок).
- Протокольный смок шлюза (два пользователя, E2E-сообщение): если есть
  `websockets` в окружении — запустите `apps/web/scripts/smoke_gateway.py`
  (перед этим `cargo build --bin rchat-server`).
