# V1: редактирование сообщений в веб-клиенте

Ты работаешь в rchat. Реализуй полный сценарий редактирования собственных
текстовых сообщений в веб-клиенте. Доведи изменения до проверенного результата.

Сначала прочитай применимые AGENTS.md, документацию FFI и реализации
`apps/web/src/components/chat/MessageBubble.tsx`, `MessageInput.tsx`,
`apps/web/src/services/api.ts`, `store.ts`, а также команду редактирования
в ядре и FFI. Проверь git status и сохрани изменения пользователя.

## Требования

- Используй существующий контракт ядра; уточни реальные имена команд,
  аргументы и ограничения. Не подменяй серверное редактирование изменением DOM.
- Добавь «Редактировать» для своих отправленных и неудалённых сообщений.
  Серверная проверка авторства остаётся обязательной.
- Заполняй поле текущим текстом, показывай режим редактирования, сохранение
  и отмену. Escape отменяет режим. Обычный черновик не должен теряться.
- Пустую или неизменённую правку обрабатывай предсказуемо. Не допускай
  повторного сохранения, пока выполняется предыдущий запрос.
- При успехе обновляй каноническое сообщение, отметку правки и связанные
  представления; корректно применяй последующее событие синхронизации.
- При ошибке сохраняй введённую правку и показывай понятную причину.
- Обработай удаление сообщения, смену чата или профиля во время правки.
  Поздний ответ не должен изменять состояние другого аккаунта.
- Если редактирование подписи вложения не поддержано контрактом, явно
  ограничь доступность действия; не теряй вложения при замене текста.

## Готовность и проверки

Проверь облачный и приватный чат, отмену, ошибку сети, чужое сообщение,
удалённое сообщение и получение правки вторым клиентом после офлайна.
Для интеграционного поведения используй имеющуюся тестовую инфраструктуру.

Запусти `npm run build` в `apps/web`; при изменении Rust/FFI выполни
соответствующие тесты и проверку актуальности JSON Schema. Обнови описание
возможности. В отчёте укажи изменённые файлы и фактические результаты проверок.
