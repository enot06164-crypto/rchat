# Веб-клиент rchat (этап H-Final)

Официальный веб-интерфейс мессенджера rchat, оформленный как реплика
Telegram WebK (тема **Amethyst Dark**): токены сняты покадрово со
скринкаста (`styles/variables.scss`), дудл-паттерн фона, капсульный
композер, плавающий FAB-карандаш.

- **SolidJS 1.9 + TypeScript (strict)** — точечная реактивность, без Virtual DOM.
- **Vite 5** — dev-сервер и сборка; **SCSS** — палитра и стили.
- **lucide-solid** — иконки (карандаш, самолётик, галочки, контекстное меню).
- Протокол — **JSON FFI без изменений** (`docs/ffi.md`): WebSocket-шлюз
  (`bindings/python/rchat/gateway.py`) проксирует `rchat_send_json` и
  ретранслирует события ядра в браузер.

## Запуск с нуля (три терминала)

```bash
# 0) один раз: собрать ядро и установить зависимости
cargo build -p rchat-ffi --bin rchat-server
cargo build --bin rchat-server
(cd apps/web && npm install)

# шлюзу нужен внешний пакет websockets (не входит в SDK):
python3 -m venv .venv-gateway
uv pip install --python .venv-gateway/bin/python websockets   # или pip install websockets в venv

# 1) сервер разработки (plaintext только для localhost)
cargo run --bin rchat-server -- \
    --db /tmp/rchat-web/server.sqlite3 \
    --listen 127.0.0.1:9000 \
    --plaintext-insecure --allow-dev-plaintext-chats

# 2) шлюз: один процесс = один профиль (данные профиля ниже)
PYTHONPATH=bindings/python .venv-gateway/bin/python -m rchat.gateway \
    --data-dir /tmp/rchat-web/alice \
    --server ws://127.0.0.1:9000 \
    --port 8080

# 3) веб-клиент (Vite проксирует /ws на шлюз)
cd apps/web && npm run dev          # http://localhost:5173
```

Для сервера с TLS (`wss://`, самоподписанный сертификат) шлюз принимает
`--tls-fingerprint` или `--tls-insecure` (Как в CLI; вне dev TLS обязателен).

## Сборка и «продакшн-превью»

```bash
cd apps/web
npm run build            # tsc --noEmit + vite build → dist/
npm run preview          # http://localhost:4173, /ws проксируется на шлюз
```

## Что уже работает

- вход/регистрация пользователя (AuthModal: вкладки Вход/Регистрация,
  фиолетовый акцент `#8774e1`, карточка 360px);
- сайдбар 360px: шапка с гамбургером, овальным поиском (radius 20px) и
  мини-аватаром пользователя с зелёным кольцом онлайна (меню профиля для
  выхода); элемент чата 72px с аватаром 54px, превью со статус-иконками
  (галочки/ошибка), фиолетовым бейджем непрочитанных; активный чат —
  залит `$accent-purple`; плавающий FAB-карандаш 54px (новый личный чат);
- шапка чата 56px (клик открывает шторку): аватар, имя, подзаголовок
  «в сети» / «был(а) недавно» (когда приходило `presence_changed`) или
  «E2E защита»; справа — иконки-заглушки v1;
- правая шторка **«Информация»** (выезжает на 360px): аватар 100px, имя,
  статус/«E2E защита», локальный тумблер «Уведомления» (не переживает
  перезагрузку) и вкладки Участники/Медиа/Файлы/Ссылки (последние три —
  честные пустые состояния, отправка вложений появится позже);
- лента — центральная колонна `max-width: 720px` на фоне `$bg-app`
  (#0e0e0e) с дудл-паттерном Telegram (opacity 0.05); капсулы дат
  («Сегодня»/«Вчера»/«16 сентября»); пузыри: входящие `#18181b` с бордером
  и хвостом слева, исходящие — градиент `#2b2140→#3d2e5c` с хвостом
  справа; в групповых чатах — имя автора цветом палитры ядра;
- **реплаи**: сообщение → ПКМ → «Ответить» — баннер в композере,
  `send_message` уходит с `reply_to_server_id`, цитата рендерится внутри
  пузыря (полоса `#8774e1`);
- **удаление** собственного сообщения (ПКМ → «Удалить», FFI
  `delete_message`): пузырь превращается в «Сообщение удалено»;
- копирование текста сообщения (ПКМ → «Копировать текст»);
- композер — «парящая капсула» (#212121, radius 24px): скрепка/смайл
  слева, textarea без рамок, справа — микрофон на пустом поле и круглая
  фиолетовая кнопка-самолётик, когда есть текст;
- кнопка «вниз» (фиолетовый кружок с бейджем пропущенных сообщений)
  появляется при прокрутке вверх; новые сообщения не автоскроллят ленту,
  если пользователь читает историю;
- мгновенный обмен: оптимистичная вставка, статусы (часы → галочка →
  двойная после прочтения, восклицание при ошибке), Enter — отправка,
  Shift+Enter — перенос строки;
- события ядра применяются реактивно: connection_state_changed,
  chat_upserted, message_received/updated, outbox_changed, receipt_updated,
  presence_changed; после `event_lagged` хранилище перечитывается из ядра.

## Понятные ограничения v1 (что НЕ входит в этап H-Final)

- Счётчик «непрочитанных» — **локальный** и не переживает перезагрузку
  страницы; отметка `mark_read` отправляется при открытом чате, чтобы
  собеседник видел «прочитано».
- `presence_changed` применяется только как подзаголовок «в сети» /
  «был(а) недавно»; пока событие не приходило в этой сессии — показываем
  «E2E защита» (честный статический факт).
- **Реакции и отправка вложений не реализованы** (на сервере нет методов
  нового API): скрепка/смайл/микрофон и пункты меню «Переслать» —
  визуальные заглушки; медиа/файлы/ссылки в шторке — пустые состояния.
- Гамбургер и иконки поиска/звонка/меню в шапке чата — заглушки v1
  (папки чатов и звонки появятся позже).
- Тумблер «Уведомления» в шторке — локальный, не синхронизируется с ядром.
- Зеркальное echo собственного сообщения от ядра (`local_id` вида `s:<id>`,
  body null) дедуплицируется по `server_id` (`message_updated` возвращает
  каноническую запись с `server_id`); история — стартовой страницей
  `get_messages(limit=100)` (пагинация «вверх» — не реализована).
- Один шлюз-процесс = один профиль. Несколько вкладок браузера делят один
  и тот же профиль (события и ответы рассылаются всем сокетам).

## Отладка

- `window.__rchat.state` — снимок reactive-хранилища в DevTools (только
  dev-сервер Vite).
- Deep-link `http://localhost:5173/?chat=<chat_id>` сразу открывает чат
  (для смоков и закладок).
- Протокольный смок шлюза (два пользователя, E2E-сообщение): если есть
  `websockets` в окружении — запустите `apps/web/scripts/smoke_gateway.py`
  (перед этим `cargo build --bin rchat-server`).
